# قفل Hidden وتجربة تسجيل الدخول

## تسجيل الدخول

أُعيد تصميم الترحيب وإدخال الرقم والرمز والتحقق بخطوتين، مع تطبيق الأسلوب نفسه على البريد وبيانات API الاحتياطية واختيار الدولة. الثيم الفاتح والداكن يستخدمان الألوان والخطوط نفسها في بقية التطبيق. الانتقالات الأفقية تستعمل سياسة التنقل المشتركة، مع موضع ثابت لزر المتابعة ولوحة الإدخال، ومحتوى قابل للتمرير للشاشات الضيقة والنص المكبر وتخطيط جانبي للوضع العريض.

الإدخال لا يفتح IME الهاتف: حقول قابلة للقراءة والتحديد مع أوامر وصول، ولوحة أرقام وحروف ورموز داخل Compose. يمكن التبديل بين الإنجليزية والعربية والسيريلية والرموز والحروف المشكّلة، ولصق نص Unicode من أي لغة. كلمات المرور تحتفظ بالمسافات وحالة الأحرف، وزر الحذف يعالج محارف Unicode المركبة من surrogate pairs. لا تعني اللوحة بديلًا متكاملًا لكل لوحات لغات العالم؛ اللصق متاح للحروف غير المعروضة. لا توجد اقتراحات أو تصحيح تلقائي لكلمات المرور. كلمة المرور ورمز التحقق وAPI hash لا توضع في SavedState.

شكل وطول رمز التحقق يتبعان TDLib، بما فيه رموز SMS النصية، ولا يُفترض أن الإرسال SMS دائمًا. اختيار الدولة وQR والاتصال عبر Proxy والمسارات الشرطية للبريد تبقى متاحة. لصق رقم دولي يتعرف على كود الدولة بدل تكراره. مساعدة نسيان كلمة مرور Telegram تفتح الإرشادات الرسمية؛ لا توجد عملية محلية تدّعي إعادة تعيين كلمة مرور الحساب.

## تفعيل Hidden

عند فتح Hidden لأول مرة، يُختار PIN من ستة أرقام ويُؤكَّد، ثم يُعرض مفتاح استعادة عشوائي من128 بت بصيغة32 رقمًا سداسيًا. يلزم الإقرار بحفظ المفتاح خارج التطبيق قبل إتمام المسار. تُحفظ بصمتا PIN ومفتاح الاستعادة بواسطة PBKDF2-HMAC-SHA256 بملحين مستقلين عشوائيين و310,000 دورة، ولا يُحفظ PIN أو مفتاح الاستعادة الخام. السجل كله، بما فيه عداد المحاولات، يُغلَّف بـ AES-GCM ومفتاح Android Keystore ويكتب ذريًا داخل noBackupFilesDir.

التحقق يجري خارج خيط الواجهة، بمقارنة ثابتة التوقيت. بعد خمس محاولات خاطئة يبدأ تأخير30 ثانية يزيد حتى30 دقيقة؛ يبقى بعد إعادة تشغيل العملية ولا يمنح إرجاع ساعة الجهاز للخلف محاولة مبكرة. انتهاء تحقق قديم بعد قفل جديد لا يمنح الفتح. ملف قفل تالف أو مفتاح Keystore غير متاح يؤدي إلى إغلاق آمن؛ لا يُستبدل السجل تلقائيًا بإعداد جديد. يشمل ذلك استرجاع ملف AtomicFile الاحتياطي عند انقطاع الكتابة.

من أيقونة القفل داخل Hidden يمكن تغيير PIN، وقفل المجموعة فورًا، وتفعيل/إلغاء بصمة اختيارية. البصمة مقصورة على BIOMETRIC_STRONG وتعتمد على فك تحدٍّ بمفتاح Keystore يتطلب تحققًا في كل استعمال؛ مجرد توافر بصمة أو وجود قفل شاشة ليس موافقة. تغيير البصمات قد يبطل مفتاحها، وعندها يبقى PIN ومفتاح الاستعادة. إعادة تفعيل البصمة بعد التحقق تُنشئ مفتاح تسجيل جديدًا.

## النسيان ودورة حياة التطبيق

الاستعادة تتحقق من المفتاح أو البصمة المفعّلة مسبقًا وتسمح باختيار PIN جديد؛ لا تعرض القديم ولا تفتح الملفات قبل إتمام التغيير. تغيير PIN يولّد مفتاح استعادة جديدًا ويبطل السابق عند الإتمام. لا يوجد خادم أو بريد استعادة تجريبي أو زر تجاوز.

القفل يعود عند مغادرة نطاق Hidden، أو خروج Activity إلى الخلفية، أو بدء عملية جديدة. المعاينة والملفات داخل المجلدات المخفية تبقى ضمن النطاق المحمي. مؤقت المحاولات يعمل أثناء عرضه وعند الحاجة فقط، وليس حلقة دائمة طوال استخدام التطبيق. مواد إعداد القفل تبقى في ذاكرة ViewModel فقط: أول إعداد يمكن متابعته أثناء التبديل لتطبيق آخر لحفظ المفتاح؛ تغيير قفل موجود يتطلب إعادة التحقق قبل استئناف الإعداد المعلّق بنفس المفتاح، فلا يضيع المفتاح الذي نُسخ أثناء الإعداد. إلغاء الإعداد أو انتهاء ViewModel يمسح المراجع والحروف المؤقتة.

واجهة القفل والمفتاح تمنع التقاط الشاشة ومعاينة المحتوى في التطبيقات الحديثة عبر FLAG_SECURE. نسخ المفتاح بطلب المستخدم يضع علامة sensitive، مع مسح مشروط بعد دقيقة أو عند إنهاء مزود الحافظة؛ لا يُمسح محتوى آخر نسخه المستخدم لاحقًا. سياسات Android قد تقيّد الوصول إلى الحافظة في الخلفية.

## نطاق الحماية

السياسة ليست مجرد بوابة تنقل: الاستعلامات الحية وصفحات Paging والبحث واختيار جميع النتائج ونوافذ المعاينة تراعي القفل. يُستبعد أيضًا محتوى المجلد المخفي وأحفاده بواسطة استعلام CTE، ويعاد التحقق من الروابط المباشرة والمصغرات ونافذة More. تُنقَّح أسماء الملفات المخفية في النشاط وإشعارات النقل، ويُوقَف الصوت والفيديو المخفيان وتُمحى بيانات الجلسة من المشغل وإشعار الوسائط عند إعادة القفل. تُزال إشعارات نتائج الملفات السابقة عند إعادة القفل أيضًا. لا تُستعاد جلسة صوت مخفية أثناء القفل. تعرض سلة المهملات البيانات المسموح بها فقط، بما فيها الصفوف المخزنة مؤقتًا بعد توسيع المجلدات. يتيح زر القفل فيها التحقق للوصول إلى العناصر المخفية واستعادتها؛ حذف السلة نهائيًا أو حذف عناصرها المحددة يتطلب التحقق عند تفعيل قفل Hidden. تنزيل مجلد لا يصدّر محتوى مخفيًا أثناء القفل.

الرفع والمزامنة يستمران؛ القراءة الداخلية الموثوقة لكشف تعارض الأسماء لا تستعمل فلترة العرض. لم يتغير تشفير المحتوى أو مفاتيحه أو مخطط قاعدة البيانات أو حزمة التطبيق أو التوقيع. الخروج من الحساب يمسح إعداد القفل المحلي لمنع انتقاله إلى حساب آخر.

هذا قفل محلي لواجهة TeleDrive، وليس تشفيرًا جديدًا للملفات أو قفلًا داخل Telegram. نسخة الملف في Telegram والتنزيلات والمشاركات السابقة لا يحميها PIN الواجهة. لا يُزامَن PIN أو مفتاحه عبر الأجهزة، وإزالة بيانات التطبيق تزيل إعداد القفل المحلي. مفتاح الاستعادة يعالج نسيان PIN مع بقاء سجل الجهاز قابلًا للقراءة؛ لا يصلح بديلاً لمفتاح Keystore مفقود أو ملف قفل تالف، ولا يستعيد مفاتيح تشفير الملفات. لا تعِد هذه الميزة بمنع مستخدم جهاز ذي صلاحيات root من تعديل التطبيق أو فهرسه.

## التحقق

تشمل الاختبارات اشتقاق الرموز ومسح مدخلات الحروف، ثبات تأخير المحاولات، استعادة الدخول وتدوير المفتاح، إلغاء صلاحية النتائج المتأخرة، تحديات البصمة، السجل المشفر والعبث به واسترجاع AtomicFile، فلترة Room والمجلدات المتداخلة والقراءة الموثوقة للرفع، وتحرير Unicode. توجد اختبارات لدورة إعداد القفل أثناء التبديل خارج التطبيق، ولاختبار الشاشة الضيقة مع تكبير النص. اختبار الجهاز يقود إعداد PIN واللوحة والإقرار بحفظ المفتاح، واختبار البداية يتأكد من الإدخال دون إظهار IME. اختبارات حساب Telegram الحقيقي والبصمات الفعلية تحتاج جهازًا وحسابًا؛ لا تُستخدم أسرار أو ملفات مستخدم حقيقية في الاختبارات.

اجتاز التنفيذ338 اختبارًا للتطبيق و66 للمكتبة المشتركة (404 إجمالًا) دون فشل، مع Lint دون أخطاء وترجمة اختبارات الجهاز. أعيد فحص التخطيط الضيق ودورة الإعداد بعد ضبط ثبات مساحة اللوحة. فحص الجهاز والبناء والنشر في GitHub يجري عبر سير إصدار ARM المعتاد؛ قياس البصمات وأداء الأجهزة الفعلية يظل خارج اختبارات المحاكي.
