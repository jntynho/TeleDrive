# الرئيسية Sand ومراجعة مشغل الفيديو

## نطاق العمل

تطبيق الاقتراح الثاني Sand المعتمد، وفحص مسار الفيديو الحالي في `PreviewScreen` و`MediaPlayer` و`PlayerControls`، مع مسار المعاينة المتوافق مع المكتبة السابقة `GalleryVideoPlayer`، ومصادر بث Telegram والملفات المجزأة والمشفرة.

هذه قائمة بالمشكلات التي أمكن إثباتها في الكود والإصلاحات المنفذة، وليست ضمانًا بعدم وجود أي خطأ على كل هاتف أو ترميز.

## الرئيسية

- بطاقة رملية واضحة، بعنوان Your library، وحجم النسخة المخزنة في Telegram، وعدد الملفات، وشريط معلومات سفلي. لا توجد نسبة استهلاك أو سعة قصوى مصطنعة.
- استخدام `remoteBytes` و`backedUpCount` بدل تقديم حجم الملفات المحلية وكأنه مخزن في Telegram. تاريخ الإضافة أو آخر نسخة احتياطية يظهر عند توفره؛ لا يُعرض تاريخ تحديث وهمي.
- إزالة وجه Collections والتبديل القديم من البطاقة.
- Browse your library يحتوي ست وجهات: All files، Activity، Favorites، Archived، Hidden، Trash. Hidden يفتح المجموعة الموجودة بالفعل.
- إزالة تصنيفات Photos/Videos/Audio من هذا القسم وروابط التصفح المكررة. تبقى هذه الوسائط في تبويباتها السفلية، والنسخ الاحتياطي في الإعدادات.
- الهيكل العظمي للتحميل يستخدم البطاقة وشبكة الوجهات نفسيهما. التفاف معلومات البطاقة يحمي التخطيط عند تكبير النص.

| الاحتفاظ بالمشغلات المتوقفة في الصفحات المجاورة | بقاء مفككات الفيديو ومصادر البيانات في الذاكرة | مشغل للصفحة المستقرة النشطة فقط؛ تحريره عند مغادرتها وحفظ حالته |
| اعتبار بداية سحب المعرض خروجًا من الصفحة | إيقاف/بدء غير ضروري حتى عند إلغاء السحب | ملكية التشغيل تتبع الصفحة المستقرة بدل كل تغير في `isScrollInProgress` |
| حفظ حالة الإيقاف التلقائي على أنها رغبة المستخدم | فقدان الاستئناف بعد التدوير أو العودة | Checkpoint يفصل رغبة المستخدم عن التعليق المؤقت ويستعيد الموضع والسرعة والصوت والتكرار |
| بدء فيديو بينما قائمة الموسيقى لا تزال تطلب التشغيل | تعارض ملكية الصوت | إيقاف مشغل الموسيقى المملوك للتطبيق قبل منح الفيديو التركيز الصوتي |
| أدوات ثابتة على بعد 108dp من الأسفل | تداخل الأدوات مع شريط التقديم أو بعضها في النوافذ القصيرة | جمع الأدوات وشريط التقديم في تخطيط واحد؛ نقل أزرار النقل إليه في الوضع القصير وإتاحة تمريره في النوافذ الأضيق |
| تجاهل الحواف الجانبية الآمنة | اقتراب الأدوات من فتحة الشاشة في الوضع الأفقي | تطبيق safeDrawing على جانبي الأدوات وأسفلها |
| التقديم عند مدة مجهولة يرجع إلى الصفر | قفزة غير متوقعة في التشغيل | تعطيل التقديم عندما يكون غير متاح، وحساب الحدود دون تحويل المدة المجهولة إلى صفر |
| سحب شريط التقديم ينافس سحب صفحات المعرض | الانتقال إلى ملف آخر أثناء البحث داخل الفيديو | تعليق تمرير صفحات المعرض طوال سحب شريط التقديم |
| هدف تقديم قديم يخفي تحديث الموضع | شريط يعرض موضعًا لا يطابق المشغل | إزالة حجب تحديث الموضع القديم، ومتابعة موضع Media3 وتغيراته مباشرة |
| الكتم يعيد الصوت دائمًا إلى 100% | قفزة صوتية غير مرغوبة | استعادة آخر مستوى صوت قبل الكتم |
| لون شريط التقديم والتعتيم يعتمد على ثيم التطبيق | ضعف وضوح الأدوات فوق الفيديو خصوصًا في Light | شريط أبيض رفيع وتعتيم أسود ثابت مستقل عن الثيم |
| اختفاء الأدوات أثناء قراءة قارئ الشاشة | فقدان إجراء التشغيل أو البحث | منع الإخفاء التلقائي أثناء touch exploration، وإضافة إجراء مسمى لإظهار الأدوات |
| اختفاء الأدوات أثناء قائمة الملف أو إعدادات المشغل | تداخل حالة القوائم مع مؤقت الإخفاء | تعطيل الإخفاء طوال السحب والقوائم والتفاعل، وإغلاق قوائم التحكم عند إخفاء الأدوات |
| إخفاء الصورة البديلة بمجرد معرفة أبعاد الفيديو | إطار فارغ قبل رسم أول صورة فعلية | إبقاء الصورة البديلة حتى حدث `onRenderedFirstFrame` |
| انطفاء الشاشة أثناء مشاهدة فيديو | انقطاع المشاهدة رغم التشغيل | إبقاء الشاشة نشطة في سطح الفيديو أثناء التشغيل/الانتظار، وتحرير ذلك مع السطح |
| فشل مفكك أول دون محاولة بديل متاح | فشل ملفات يمكن تشغيلها بمفكك آخر على الهاتف | تفعيل decoder fallback في Media3؛ لا يضيف ذلك ترميزات غير موجودة |
| اختيار مسار ترجمة/صوت غير مدعوم | طلب لا يمكن للمشغل تنفيذه | تعطيل الخيارات غير المدعومة، وتصحيح توصيف قنوات الصوت، وحفظ اختيار ترجمة مجهولة اللغة كـ und بدل Off |
| مساران مختلفان لأدوات الفيديو | اختلاف السلوك والشريط بين المعاينتين | استخدام PlayerControls نفسه في المعاينة المتوافقة، مع دورة حياة وحفظ حالة مماثلين |

## البث والموارد في الخلفية

| المشكلة | الإصلاح |
| --- | --- |
| انتظار Hot Flow بعد طلب البيانات قد يفوّت تحديث الاكتمال ويظل منتظرًا | التحقق المحدود زمنيًا من حالة الملف لدى TDLib حتى تغطي البيانات النطاق المطلوب؛ التحقق محلي عبر TDLib وليس استعلام HTTP متكررًا |
| DataSpec بطول يتجاوز بقية الملف | حصر طول القراءة في البيانات المتاحة والإبلاغ الصحيح عن موضع يتجاوز نهاية الملف |
| قراءة فارغة قبل نهاية النطاق تُعامل كاكتمال عادي | EOFException عند الانقطاع المبكر لتمييز الملف الناقص/تعثر الشبكة عن النهاية الطبيعية |
| مصدر أحادي يعاد فتحه بمعرّف وحجم قديمين | تصفير بيانات الحل عند الإغلاق ثم إعادة الحل عند الفتح التالي |
| قراءة native قصيرة لرأس التشفير أو الإطار | تجميع الرأس والإطار كاملين قبل فحص المصادقة، بدل تفسير القراءة القصيرة كفشل تشفير؛ اختبار فعلي بإرجاع 7 بايت فقط لكل قراءة |
| الجزء التالي يبدأ تنزيله مسبقًا دون تحريره عند إغلاق الفيديو | تتبع الجزء المسبق وتحريره مع الجزء الجاري |
| فشل إغلاق قناة قد يترك حجز الكاش مفتوحًا | إغلاق حجز الكاش في finally حتى إذا فشل إغلاق القناة |
| فشل إنشاء قناة فك التشفير قد يترك القناة الخام مفتوحة | إغلاق المصدر الخام عند فشل إنشاء القناة المشفرة |
| تبديل حساب المكتبة أثناء قراءة فيديو من المسار المتوافق | رفض القراءة عند اختلاف الحساب أو إغلاق المكتبة، قبل قراءة النطاق وبعدها |
| استثناء أثناء استعادة موضع التشغيل في المسار المتوافق | عرضه كخطأ قابل لإعادة المحاولة بدل ترك استثناء إعداد غير معالج |
| قراءة صفر بايت من القناة البعيدة تُفسر كنهاية ملف | احترام عقد SeekableByteChannel وإرجاع صفر عند عدم وجود مساحة في المخزن |

## التحقق وحدوده

- اختبارات تفاعل فعلية لأزرار الفيديو باستخدام Compose وPlayer حتمي: الإيقاف أثناء buffering، الكتم واستعادة الصوت، التقديم وحدوده، وتعطيل التقديم غير المتاح، وعدم تداخل أدوات الوضع القصير.
- اختبارات استعادة الموضع والسرعة والصوت والتكرار، وحفظ رغبة المستخدم أثناء تعليق دورة الحياة.
- اختبارات مصادر Telegram: فقد تحديث الاكتمال، طول النطاق، الانقطاع المبكر، إعادة الفتح، وتنظيف الأجزاء المحملة مسبقًا.
- اختبارات التنقل الحالية تشمل الوجهات الست وفتح Hidden، وتستخدمها أيضًا اختبارات Light/Dark/AMOLED.
- اللقطات الموجودة في `app/build/design-previews` ناتجة عن عرض Compose الفعلي ببيانات اختبار، وليست صورًا مولدة بالذكاء الاصطناعي.
- يلزم اختبار يدوي على هاتف بحساب Telegram: ملفات كبيرة ومشفرة ومجزأة، انقطاع الشبكة والعودة، تنوع ترميزات الأجهزة، التدوير الفعلي، وتنافس التركيز الصوتي مع مكالمة. اختبارات المضيف لا تثبت أداء الإطارات أو سلامة كل ترميز على جميع الأجهزة.
- تشغيل الفيديو في الخلفية يظل تابعًا للإعداد الموجود؛ لم يُضف هذا التعديل خدمة فيديو مستقلة أو PiP أو مكتبة ترميزات جديدة.

## نطاق توزيع الإصدار

حسب الطلب، يبني مسار الإصدار وينشر ARM64 وARM32 فقط. لم يعد يبني x86_64 كإصدار. فحص ملفات ARM الموقعة يتحقق من الحزمة والتوقيع ونسخة Android والنشاط الرئيسي؛ يبقى محاكي x86_64 لاختبارات debug الداخلية فقط.
